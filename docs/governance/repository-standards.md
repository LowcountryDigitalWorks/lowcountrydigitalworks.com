# Repository Standards

## Ownership

Company repositories belong to the `LowcountryDigitalWorks` organization. Client repositories should ordinarily belong to the client.

## Visibility

- public for approved company websites, open examples, and reusable non-sensitive tooling;
- private for internal operations, customer work, confidential documentation, credentials-adjacent records, and proprietary client deliverables.

## Minimum repository contents

Every maintained repository should include, as applicable:

- README;
- ownership and purpose;
- architecture or technical notes;
- setup/build instructions;
- testing instructions;
- deployment and rollback;
- security reporting guidance;
- changelog or release history;
- license status;
- branch and pull-request workflow.

## Naming

Use clear lowercase names with hyphens, except a domain repository may use the exact domain name. Avoid names tied to an individual account when the asset belongs to the company or client.

## Automation

Prefer repository-controlled validation that is portable and understandable. Shared workflows should be introduced only when centralization reduces duplication without hiding important behavior from the consuming repository.
